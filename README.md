## 주요 기능

### 회원 등록 / 조회

1. 회원 이름 필수  
필수 입력값(name) 검증을 위해 DTO에 Bean Validation(@NotEmpty)을 적용했습니다.  
컨트롤러에서는 @Valid와 BindingResult를 활용하여 검증 결과를 처리하고,  
검증 실패 시 사용자에게 에러 메시지를 표시하도록 구현했습니다.


2. 회원 이름 중복 비허용  
중복 회원을 방지하기 위해 service 테이블에 name 필드를 이용한 검증 메서드를 추가하였습니다.

### 상품 등록 / 조회 / 수정

1. 상품 수정 시 자동 DB 반영  
영속성 컨텍스트의 변경 감지(Dirty Checking)를 활용하여,  
엔티티 조회 후 값만 변경하고 트랜잭션 종료 시점에 자동으로 DB에 반영되도록 구현했습니다.

### 상품 주문 / 조회 / 취소

1. 엔티티 설계  
다대다 관계(Order-Item)를 중간 엔티티(OrderItem)로 분리하여,  
주문 수량과 가격 등 추가 정보를 함께 관리할 수 있도록 설계했습니다.


2. 주문 시 연관 엔티티 동시 저장  
주문(Order)과 주문상품(OrderItem), 배송정보(Delivery)가 함께 저장되도록  
연관관계에 CascadeType.ALL을 적용했습니다.  
이를 통해 주문 생성 시 연관관계 메서드로 객체를 주입하면  
별도의 저장 호출 없이도 함께 영속화되도록 구현했습니다.


3. 주문 및 취소 시 재고 반영  
주문 및 취소 시 상품 재고에 자동으로 반영되도록 비즈니스 로직을 엔티티 내부에 위치시켰습니다.  
주문 시 OrderItem 생성 과정에서 Item.removeStock()을 호출하여 재고 차감  
주문 취소 시 Order.cancel() → OrderItem.cancel() → Item.addStock() 흐름으로 재고 복구  
객체 간 연관관계를 활용하여 재고 변경 로직이 자연스럽게 동작하도록 구성했습니다.


4. 주문 검색 기능  
회원명과 주문 상태를 조건으로 주문을 조회할 수 있도록 구현했습니다.  
@ModelAttribute를 활용하여 요청 파라미터를 검색 조건 객체로 바인딩하고,
해당 조건을 기반으로 주문 목록을 조회하도록 구성했습니다.

## 확장 및 미구현 기능

본 프로젝트는 JPA 학습을 목적으로 설계되었으며, 일부 기능은 확장성을 고려하여 구조만 구현된 상태입니다.

- 주문 기능은 다수 상품 주문이 가능하도록 설계되었으나, 현재 UI에서는 단일 상품 주문만 지원합니다.


- 주문 총액 계산 로직은 구현되어 있으나, 실제 화면에는 아직 반영되지 않았습니다.


- 주문 상품 가격은 향후 할인 정책 적용을 고려하여 별도로 관리하도록 설계했습니다. (현재는 상품 가격과 동일)


- 배송 정보는 별도의 값으로 관리할 수 있도록 설계했으나, 현재는 주문 회원의 주소를 그대로 사용합니다.


- 배송 상태에 따른 주문 취소 제한 로직은 구현되어 있으나, 배송 상태 변경 기능은 포함되어 있지 않습니다.


- 카테고리 및 상품 간 다대다 연관관계, 계층형 카테고리 구조를 설계했으나 관련 기능은 구현하지 않았습니다.


- 다양한 상품 타입을 고려한 상속 구조를 설계했으나, 현재는 도서(Book) 상품만 사용합니다.
